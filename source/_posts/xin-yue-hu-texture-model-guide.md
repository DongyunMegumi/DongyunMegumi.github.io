想让自己的角色使用心月狐这套Blender渲染模板，需要同时准备贴图和模型数据。只换颜色图可以看到基础效果；要让脸影、头发高光、透明与描边按预期工作，还要知道每个入口实际读取什么。

这篇文章以《心月狐打包.blend》的有效接线、原纹理通道和模型数据为案例，分成“入口规范”和“制作方法”两部分。检查基准为2026年10月8日；这是该模板的使用说明，不能当作游戏官方通用资产规范。原图数值、节点计算与建议起步值分别说明。

**先记住最常用的组合：衣服D / N / FTM / RGID，脸D / SDF / HET，头发D / FTM / HM / HN，眼睛D / HET。** 一套最终PNG往往由多份独立源图打包而成，Alpha、UV1和顶点色也可能装的是控制数据。

本文讲解的是Blender模板。跨引擎移植还需另外核对shader实现、色彩空间、透明与描边流程，不能仅凭图齐全就认定Unity画面已经一致。

## 第一部分：原工程怎样读取你的数据

<a id="spec-1"></a>

### 1. 按心月狐的组织方式，到底有几张

文件名统一省略 `T_R2T1XinMd10011` 前缀。1K=1024、2K=2048，以下尺寸都来自原图。

| 部位/图集 | 自己角色对应的文件 | 原图尺寸 | 数量 |
|---|---|---|---:|
| Cloth 服装图集 | Cloth_D、Cloth_N、Cloth_FTM、Cloth_RGID | 均2K | 4 |
| Up 上身图集，包括其UV里的皮肤 | Up_D、Up_N、Up_FTM、Up_RGID | 均2K | 4 |
| Down 下身图集，包括其UV里的皮肤 | Down_D、Down_N、Down_FTM、Down_RGID | 均2K | 4 |
| Bangs 刘海图集 | Bangs_D、Bangs_FTM、Bangs_HM、Bangs_HN | 2K、512、2K、256 | 4 |
| Hair 后发图集 | Hair_D、Hair_FTM、Hair_HM、Hair_HN | 2K、512、2K、256 | 4 |
| Face 脸 | Face_D、Face_HET、适配脸UV的SDF | 2K、256、原SDF为1K | 3 |
| Eye 眼睛 | Eye_D、Eye_HET | 2K、256 | 2 |
| Up 特效，可选 | Up_FX | 2K | +1 |
| Tail 尾巴完整原槽位，可选 | Tail_D、Tail_N、Tail_RGID、Tail_ID、角色_M | 1K、1K、1K、512、2K | +5 |

前三套衣服12张、前后发8张、脸3张、眼睛2张，合计25张。当前Up内部接着 `心月狐UP_FX`，保留流动发光就是26张；再照原尾巴的五个角色相关槽位准备，是31张的参考清单。尾巴N等槽位存在不代表每个输出当前都参与可见效果，详见第7部分。

这不是必须达到的数量。前后发共用同一张图集可以只做一套4张；三套服装合并图集也可减少数量；关闭眼透/局部调色可以省HET；没有空间变化的透明控制可以用常量代替FTM。

计数不包括能复用的HR高光色带、Matcap、眼睛高光图集、毛纹高度图、Flow扰动图和环境HDR。原脸FTM虽留在节点里，其输出未用于脸的主效果，未列入必做清单。图片名里的 `.001` 常是同一素材的Blender数据副本，也不是必须再画一张。

<a id="spec-2"></a>

### 2. 先给模型分材质、整理UV

心月狐有对应 `MI_R2T1XinMd10011Cloth/Up/Down/Bangs/Hair/Face/Eye/Tail` 的材质。Cloth/Up/Down是图集与材质的划分，不能仅凭名字判断它只包含布料；原Up、Down颜色图中也有身体皮肤。

你的模型可以沿用这个分组：脸、眼球、刘海、后发、上身、下身、其他服装。要共用一张图集的网格必须在同一套UV约定下取图。每套D、N、FTM、RGID或D、HM、HN虽然分辨率不同，UV岛位置必须一致。

颜色与控制图都按自己的UV做。原心月狐的图只能参考画法，不能直接匹配另一张头或另一套衣服UV。把原模板复制给自己后，逐个替换角色相关图片；未换的入口仍会读旧角色的图。

### 3. 三套衣服：每套四张，分别怎么做

<figure>
<a href="/img/xin-yue-hu-texture-model-guide/01-clothing-channels.png" target="_blank" rel="noopener"><img src="/img/xin-yue-hu-texture-model-guide/01-clothing-channels.png" alt="三套服装真实通道" loading="lazy" decoding="async"></a>
<figcaption>原贴图的通道诊断预览；黑白格表示该通道值，不能当作材质贴图使用（点击图片查看大图）</figcaption>
</figure>

#### 3.1 D：RGB颜色，Alpha闭塞/发光

**原案例：** `T_R2T1XinMd10011Cloth_D.png`。RGB有红布、浅色毛饰、金色装饰的固有色与纹样；Alpha常见中性值是102/255≈0.4，部分区域接近0。Up、Down、脸、前后发的D也常用102作中性值。这来自原图采样，不表示所有像素都必须102。

**你制作：** RGB画颜色、妆纹、布纹和必要的手绘细节；不要把固定方向的大面积受光、投影和镜面亮斑全画死。Alpha单独保存为控制通道，它不是这一套衣服的透明度。

当前组 `鸣潮贴图转换` 的计算是：

```
闭塞输出 = clamp((A - 0.02) / 0.23, 0, 1)
发光输出 = clamp((A - 0.50) / 0.50, 0, 1)
```

| Alpha的8bit值 | 当前意义 | 制作建议 |
|---:|---|---|
| 0～5 | 闭塞接近最强，发光为0 | 真正想压暗的缝隙、小范围遮挡 |
| 约35 | 闭塞输出约0.51 | 中等闭塞起点，按画面调整 |
| 64～127 | 闭塞已满值，发光为0 | 无闭塞、无发光区域；照原图可用102 |
| 约191 | 闭塞满值、发光约0.50 | 需要发光的装饰 |
| 255 | 闭塞满值、发光控制满值 | 不要整张普通衣服无意导成255 |

闭塞输出1表示不额外压暗，0表示更受闭塞遮挡；最终阴影还要与主光照等合成。制作AO时先得到白=无遮挡、黑=遮挡的黑白图，再映射到Alpha约5～64；不需要AO的区域可按心月狐填102。64是可用的无闭塞起点，102是原图常见中性值。

**接入：** D的Color接转换组D，Alpha接D_alpha；图片sRGB，Alpha按打包数据保存，原D使用CHANNEL_PACKED。PNG在文件浏览器里可能半透明，这不等于衣服在工程里半透明。

**检查：** 暂关额外发光，用侧光看接缝是否只是局部压暗。普通区域若无灯也异常亮，先检查Alpha和发光支路；不要先把阴影颜色拉黑。

#### 3.2 N：RG法线，Alpha粗糙度

**原案例：** `Cloth_N.png` 为2K，常见平坦RGB约(127,128,0)，所以看起来偏黄绿色。不是法线导出坏了。N的Alpha有例如46、207、245等不同灰度，当前直接送给粗糙度。

| 通道 | 当前读法 | 怎样制作 |
|---|---|---|
| R/G | 法线两分量，送 `绿法线转法线` | 烘焙高模褶皱/缝线/凹凸，再核对方向 |
| B | 当前转换不使用输入B恢复法线 | 照原图可留0，不把它当粗糙度 |
| A | 粗糙度 | 越黑越光滑，越白越粗糙 |

建议起点：粗布A约200～245，皮革约100～180，光滑装饰约40～100。这些是新图制作起点，不是从原图给每块材质反推的硬性规定；金属也能很粗糙，不能把“金属”与“低粗糙度”绑定。

在美术源文件里保留普通法线和粗糙度两份；最后把法线RG和粗糙度A打成一张N。当前组会反转、重建分量，不能只凭OpenGL/DirectX导出名称保证完全匹配。用一条确认凸起的缝线试灯：凹凸反了就核对通道方向，先别改模型。

**接入：** N.Color→N，N.Alpha→N_alpha，Non-Color。无凹凸的初稿可用RG=(0.5,0.5)，B=0，Alpha按表面粗糙度。它不需要借助普通法线图的蓝色外观。

#### 3.3 FTM：R透明，G金属，B战损

**原案例：** `Cloth_FTM.png` 为2K，R大多白，G随区域变化，B常见126附近。原Up、Down也有不同强度的G；原图不是只有黑白两档金属度。

| 通道 | 工程含义 | 自己怎么画 |
|---|---|---|
| R | 不透明度 | 实体衣服255；镂空0；薄纱/柔边按需要用灰 |
| G | 金属度 | 普通布料0；纯金属可先255；混合效果用灰 |
| B | 转换组提供战损输出 | 当前三套普通衣服主链未使用它，照原图留126或初版0均不影响这一路 |
| A | 当前转换组不读取 | 不用它放当前透明控制 |

可直接照着填的初稿：普通实体布料RGB=(255,0,126)，纯金属RGB=(255,255,126)，镂空非金属RGB=(0,0,126)。这些是按当前接线构建的起点，不代表真实原贴图只有三种颜色。

**接入：** Color→FTM，Non-Color。不要把常规ORM（AO/粗糙度/金属）的RGB打包图直接放进这个入口，通道不相同。

**检查：** 先把R单独看成黑白，确认需要镂空的位置才变黑；再看G，确认金属装饰与布料分开。Alpha即使全黑也不是这个入口判断透明的依据。

#### 3.4 RGID：低灰度分区编号

**原案例：** 三套服装RGID常见像素是RGB=(0,0,0)、(16,16,16)、(32,32,32)、(48,48,48)、(64,64,64)。它们是编号，不是表面的颜色，也不是R/G/B各放一个独立遮罩。

转换组先做Gamma约0.454545，再进 `ID选区`。对于三个通道相同的8bit灰度：

| 原像素灰度 | 转换后的ID位置，约 |
|---:|---:|
| 0 | 0.000 |
| 16 | 0.284 |
| 32 | 0.389 |
| 48 | 0.468 |
| 64 | 0.534 |

原Down有位置0.2833的选区接Matcap，有位置0.4583的选区接另一层Matcap，也有0.5333的选区参与调色/阴影混合。因此你可以照原图用这些低灰度，但必须核对复制的选区到底接了什么。不能说“64统一代表金属”：不同材质中的接线用途不完全一样。金属度本身由FTM.G决定。

**你制作：** 给希望分开调整的布料、饰物、皮革等区域分配不同编号，用同值RGB画清楚，保留区域说明。将对应 `ID选区` 的位置调到上述解码值；范围与过渡控制误差和边界。

**检查：** 暂把选区结果用黑白显示，白应只覆盖目标区域。新图若使用更宽的0～255编号也可以，但要重调位置；只改图、不改原位置会选错。

#### 3.6 Up_FX：基础四张之外的流动发光

当前Up的 `Group.005` 使用 `心月狐UP_FX`，未静音。它内部两次读 `T_R2T1XinMd10011Up_FX.png`：一份Color经过运动的UV，另一份Alpha提供原UV上的范围，二者相乘，再经Gamma等叠加到颜色。

保留这个效果时：FX.RGB画希望流动的亮纹，FX.A画允许显示它的区域；Alpha=0的地方不显示这层。原图2K、sRGB、CHANNEL_PACKED。它与D.Alpha的普通发光编码不是同一入口。

自己的衣服不需要流动纹样，可以关闭/旁路这一组，从而仍是基础四张。不要仅换D却让内部FX继续读取心月狐的UV图。

### 4. 脸：D、SDF、HET分别负责什么

<figure>
<a href="/img/xin-yue-hu-texture-model-guide/03-face-eye-channels.png" target="_blank" rel="noopener"><img src="/img/xin-yue-hu-texture-model-guide/03-face-eye-channels.png" alt="脸和眼睛通道" loading="lazy" decoding="async"></a>
<figcaption>原贴图的通道诊断预览；黑白格表示该通道值，不能当作材质贴图使用（点击图片查看大图）</figcaption>

#### 4.1 Face_D

原 `Face_D.png` 为2K，RGB画肤色、腮红、嘴唇、眉眼纹样；Alpha常见102。可以用自己的脸部颜色图，但要检查Alpha；当前脸也使用D.Alpha的闭塞输出。

原Face主光照使用平法线常量，并没有普通脸N贴图。当前留着的Face_FTM图也没有把透明/金属/战损输出送入脸的可见主链。因此准备脸D、SDF和需要的HET即可，不能见到一个旧图片节点就判断必须再画一张。

#### 4.2 Face_SDF：随光角度改变的阴影阈值

原资源为 `T_FemaleMFace_SDF.png`，1K，放在 `基础光照` 内部的Image to Closure。它是有多个通道的数据图，当前脸SDF函数的解码选项取：

```
S = (R + B + A) / 3
t = 0.5 - 0.5*cos(水平光角)
明面 = smoothstep(t - 过渡, t + 过渡, S)
```

这里S、t取0～1。S高的区域在光转到侧后方时更晚进入阴影。当前参数以180°为全角范围；正面t=0，60° t=0.25，90° t=0.5，120° t=0.75，背面t=1。脸过渡约0.05。

灯从左右照时，当前配置按方向切换U与1-U采样，镜像中心是U=0.5；左右交换选项也参与决定分支。它依赖头部前方向和上方向，不能只看贴图有没有加载。

**制作要求：** 每个脸UV点的灰度记录它进入阴影的角度，鼻子、脸颊、嘴周的变化需要按自己的脸设计；不是把普通AO另存为SDF。用不同角度的目标阴影参考来确定阈值，且同一侧各角度阴影应有可用单阈值表达的顺序。如果某点反复亮暗，一张这种阈值图无法完全表达。

**一张灰度图怎么交：** 灰度值同时写进RGBA四个通道，Non-Color，CHANNEL_PACKED。这样当前RBA均值才恰好等于你的灰度。不要交“RGB灰度、Alpha全255”的普通PNG：当前会读成(2*S+1)/3，阈值被抬高。镜像UV、头部方向、阴影样式也要满足当前配置，通道格式对不等于所有脸都能直接通用。


**接入：** 脸D在根材质，SDF在主光照所用组内部。先让该组成为自己角色独立副本再换内部图片；仅复制最外层材质不会自动复制里面的共享组。

**检查：** 正面左右脸都正常受光；±60°鼻部/脸颊阴影能换边；侧后方阴影继续增长；转头后阴影仍跟着头的朝向。不能只在固定灯光、固定相机下看一次。

#### 4.3 Face_HET：供eye_mask和局部调色使用

原 `Face_HET.png` 为256，RGB基本黑白；`.001`为同素材的另一数据副本。根材质两次采样，一路Non-Color灰度与0.5做大于比较，另一路sRGB灰度相乘，得到 `eye_mask`。对于纯黑白图，白得到1，黑得到0。还有1-HET参与局部调色系数，该调色组当前处于静音状态。

Face_HET不是SDF，不能决定鼻影形状。原图白块在其特定UV位置，不能仅看图片白块就认定它是你模型眼睛的坐标。自己的图要按自己脸UV制作与预览 `eye_mask`，需要允许眼透叠加的范围设白，其他位置设黑；若需要眉睫也参与，范围一起设计。检查遮住眼睛的刘海下是否只出现预期内容，不要把耳朵、脖子透出来。

根材质有两份HET采样时都要换到对应的新素材；保留原采样方式。最终眼透还依赖刘海的NPR输出、眼透强度和视角控制，HET放上去不代表完整系统已适配。

关闭眼透和这一路局部调色后可省HET，脸就D+SDF两张。

### 5. 刘海和后发：D、FTM、HM、HN

<figure>
<a href="/img/xin-yue-hu-texture-model-guide/02-hair-channels.png" target="_blank" rel="noopener"><img src="/img/xin-yue-hu-texture-model-guide/02-hair-channels.png" alt="头发通道" loading="lazy" decoding="async"></a>

#### 5.1 Hair/Bangs_D

原图各2K，RGB有冷白发色、发束深浅、根梢与细节，Alpha常见102。制作自己的发色与手绘纹理，Alpha按闭塞约定处理。这个Alpha不是当前发片透明入口。

#### 5.2 HM：三路不同的美术控制

原刘海和后发HM各2K，当前 `头发高光分支` 与 `基础光照` 的真实接线如下。

| 通道 | 用途 | 原案例观察 | 自己怎么做 |
|---|---|---|---|
| R | 高光允许遮罩，乘到高光上 | 大部分黑，部分发束上的条状区域白 | 希望出高光的发束区域画白，排除区域黑，边缘可灰 |
| G | 主光照阴影偏移的附加控制 | 有发束纹理，常见底值约65～82 | 初版可先0；需要调整局部二分时再画灰，当前贡献约G*0.1 |
| B | 高光曲线参数，参与宽度/凸起形状 | 刘海有区域变化；后发B基本黑 | 初版0可参考后发；刘海需要局部形状变化时再绘制 |

HM.R可以有条状形，但它依然是“允许动态高光的区域”：最终高光还受HN、灯光、视角、偏移/宽度影响；不是涂白就永远固定白。

HM.B不是粗糙度，也不能简单断言白=一定更宽。它与全局宽度、凸起强度共同计算；用一束头发对比不同B值后，再扩展到全头。

#### 5.3 HN：当前高光读取G，不是普通法线

原HN只有256×256，当前分支只取G通道作为高光曲线的输入场，图解里的原G可见发束区域渐变。它没有送进普通法线解码器，不能把紫色头发法线直接放这个槽。

做新角色的可执行起步方法：每束头发单独建立连续灰度梯度，尽量让同一视觉高光带经过的位置具有相近的G值；梯度写入G，R/B先留常量。可以先试根到梢的梯度，再用高光“偏移、宽度、翻转方向”找位置；原图并不能证明所有发束都是同一根梢线性梯度，需要根据发束实际形状修正。

检查不同发束是否接成连贯的带；若断裂，先核对G值是否连贯、HM.R是否允许；如果整个高光带位置错了，先调偏移或HN场，不要仅加大系数。256是原案例尺寸，自己更细的发束可以提高尺寸，但做对场比盲目4K更重要。

#### 5.4 FTM：主要读R参与刘海NPR透明

原前后发FTM各512，G大多0、B常见126；刘海R有灰色变化，后发R大多白。当前FTM.R写到“头发透明”AOV，刘海的NPR树再结合折射、顶点色与眼透处理，不是一个通用材质Alpha直接混合就结束。

需要发片镂空/柔边或刘海透明范围时，R按目标画：实心255、去掉0、中间过渡用灰。后发实体发块、不需要空间变化时，FTM可以换为RGB=(1,0,126/255)常量，省一个文件。不要直接删图而让旧图片/默认值继续生效。

#### 5.5 HR：共享的高光色带

原 `T_R2T1XinMd10011Bangs_HR.png` 是512×4，前后发都用其sRGB数据副本。它沿高光曲线取颜色，不按角色发束UV贴上去。复制发材质时可以继续复用，最后调色；换单色高光模式也可不用HR。

原头发高光参数可作参照，不能直接保证适合新图：

| 参数 | Hair后发 | Bangs刘海 |
|---|---:|---:|
| 模式 | 渐变高光 | 渐变高光 |
| 系数 | 0.745 | 0.745 |
| 偏移 | -0.17 | -0.12 |
| 宽度 | 6.92 | -1.67 |
| 凸起强度 | 10.79 | 10.79 |
| 运动强度 | 0.35 | 0.35 |
| 光照影响强度 | -0.48 | -0.48 |
| 高光明度 | 1.00 | 0.55 |

这套宽度是模块内部控制值，允许负数，不是毫米或屏幕像素。前后发原参数差异明显，所以应分别调。

### 6. 眼睛：D、HET，以及可复用的高光资源

**Eye_D：** 原图2K，RGB已经有虹膜、瞳孔、眼白和手绘细节。按自己眼球UV画，别把大面积方向性高光当成必须画死的部分；动态点高光另有模块。原D.Alpha多为128，当前虽然接入转换组，但闭塞/发光输出未接到眼睛的对应主链，不能把128当眼睛透明度。

**Eye_HET：** 原图256、sRGB，是最终HSV调色Factor：白允许调色，黑保留输入，灰混合。想只改虹膜就把虹膜区域画白，眼白画黑。这与Face_HET的eye_mask是两张用途不同的图。保持当前不需要局部调色时可设常量或旁路，省HET。

**T_HDMF_EM.png：** 512、Non-Color，提供视差与高光素材图集。可以复用，不必每个角色画一份。当前眼睛D经过Parallax UV采样，点高光也有自己的UV/图集处理；先确保眼睛UV中心、比例与视差采样正确，再调高光位移、大小、强度。

原眼睛高光起点：细节强度0.4583、点高光强度0.5333、位移(0.19,-0.14)、大小0.06，第二高光强度0；点高光旋转有时间接线，不能只看未连线默认值。需要静止示例时另行关闭/固定这一动画来源。

根材质 `Image Texture`=D，`.001`=HET，`.006`=EM资源；`.002`的第二高光旧图没有接入当前主链，不用因它还在节点中就新增一个制作任务。

### 7. 尾巴：先分清普通表面和体积毛

原Tail不是普通Hair模板，它混合普通表面、分区透明、视角轮廓效果和毛层：

<a id="spec-8"></a>

### 8. 身体、眉睫、描边与灯光

**身体皮肤：** 原Up/Down图集已有皮肤区域，不一定另开Body贴图；N.A控制皮肤表面粗糙度，FTM.G在非金属皮肤区域应接近0，SSS/阴影色可由材质调。身体不用脸的SDF。

**眉毛、睫毛：** 实体网格可以纯色或共用脸图集；发片需要其材质实际透明入口的遮罩。不要把脸D.Alpha默认当成睫毛透明。数量取决于你的材质/UV划分，原八类图集之外不自动再加固定数量。

**描边：** 不必多画一张“描边贴图”。原 `描边材质` 读COL0顶点色G控制宽度、读UV1里的特殊压缩法线，并使用“描边排除”属性。UV1是编码数据，不是随便展UV或复制UV0能替代。换自己的模型时，需要正确准备这些数据或使用适合自己模型的法线来源；只把描边材质赋上去并调宽度，不能保证原效果。

**脸边缘光：** 当前脸根材质还读顶点色B控制部分边缘光。顶点色与图片是两种不同的数据，缺这些控制时即使贴图都齐，也会出现效果差异。

**灯光/画面：** 复制现有灯光与材质可以继续用，但灯光方向、强度、世界、阴影和色彩管理要一起检查。源工程Standard、Look None、曝光0、Gamma1是已导出的参考设置，不代表用户此刻每项都未改动。亮色、阴影色、SSS、边缘光、Matcap强度主要是可调参数，不要求每个效果再增加一张图。

<a id="spec-9"></a>

### 9. 导出与接入的一次完整流程

1. 分材质、确定哪些网格共用图集，完成自己的UV；颜控图都沿用同一图集的岛位。
2. 先制作/接入D，检查RGB与Alpha，不要等所有控制图都完成才发现UV错位。
3. 衣服做普通法线源图和粗糙度源图，再打包N；用一条凸起缝线验方向。
4. 单独画透明、金属、战损源通道，打包FTM；单独画分区编号得到RGID，登记编号用途。
5. 脸使用自己的SDF，保留完整RGBA数据、镜像约定和头部方向；需要眼透再做Face_HET。
6. 头发先HM.R和HN.G建立高光范围与位置，再调HM.G/B；必要时画FTM.R，先单色后渐变调高光。
7. 眼睛先D/UV，再视差、动态高光与HET；最后处理Up_FX、尾巴等附加部分。
8. Blender中D/FX等颜色图用原用途的sRGB；N/FTM/RGID/HM/HN/SDF用Non-Color。原HET、HR、毛纹/Flow存在各自采样设置，保留对应入口的设置，不能统统按后缀一键改。Alpha存储独立数据时保留RGBA并按打包数据使用。
9. 外层材质复制后逐个检查共享内部组和图片，尤其SDF、FX、Tail图像闭包。仅换根节点的D不够。
10. 最后处理描边模型数据、边缘光、SSS、Matcap与特效，固定灯光转完整视图，固定模型转灯光，分别检查。

### 10. 验收时逐项看什么

| 检查点 | 通过的样子 | 常见原因 |
|---|---|---|
| 基础色 | 花纹、脸妆、虹膜落在自己的UV位置 | 未替换旧图或UV不一致 |
| 闭塞/发光 | AO只压暗目标局部，普通布料不自行发亮 | D.Alpha误填255或源图Alpha丢失 |
| 法线 | 同一凸缝从两侧打光符合凸起表现 | 解码/绿色方向或UV切线问题 |
| 粗糙度/金属 | 布、皮、金属各有预期亮斑 | N.A、FTM.G混放成ORM |
| 分区 | 每层调色/Matcap只改选中的区域 | RGID位置未经过Gamma换算或旧节点用途不同 |
| 脸SDF | 正面自然、左右阴影换边、转头仍跟随 | SDF.A不对、镜像中心错、头部方向没跟随 |
| 头发高光 | 发束连贯、灯/视角变动没有意外整片亮白 | HM.R太大、HN.G不连贯、原偏移/宽度不适合 |
| 眼透 | 刘海下只出现需要的眼部内容，侧面控制合理 | Face_HET未按新UV做、NPR/视角设置未适配 |
| 描边 | 近远、侧背面都连续，局部粗细可控 | UV1编码、顶点色G或排除属性缺失 |
| 尾巴毛层 | 有真实层值与几何，疏密和轮廓随设置改变 | 只换图，修改器仍关闭或属性缺失 |



## 第二部分：怎样从源图和模型做出这些数据

<a id="make-1"></a>

### 1. 先准备哪些工作文件

不要一开始就直接在最终打包图里混着画。美术制作阶段保存独立源图或图层，最后再打包：

| 工作文件/图层 | 最后放哪里 |
|---|---|
| 衣服、脸、头发、眼睛固有色 | 各部位D.RGB |
| AO/闭塞工作图 | 经过数值映射后放D.Alpha；眼睛当前对应输出未使用 |
| 普通切线法线源图 | 按当前解码适配后放衣服N.RG |
| 粗糙度黑白图 | N.Alpha |
| 不透明度黑白图 | 衣服/头发FTM.R；尾巴走其实际专用入口 |
| 金属度黑白图 | 衣服FTM.G |
| 分区编号图 | RGID.RGB |
| 头发高光允许区、二分偏移、形状控制 | 分别HM.R/G/B |
| 头发高光输入场 | HN.G |
| 面部阴影阈值场 | SDF数据通道 |
| 眼透范围/眼睛局部调色范围 | 对应Face_HET或Eye_HET |

例如一套衣服最终交四张图，美术源文件里可以有颜色、AO、普通法线、粗糙度、透明、金属、ID七类图层。这能让你分别修改效果，而不是每次都拆最终PNG。

图层透明度与图片Alpha通道是不同东西。做D/N/SDF等打包图时，检查保存后实际RGBA像素；不要用降低整个图层不透明度的方法代替写数据Alpha。保留PSD/KRA或其他可编辑源文件，最终导出有Alpha的PNG/TGA，数据图不经过额外调色或显示变换。

<a id="make-2"></a>

### 2. 正确的制作先后顺序

1. 确认材质划分和图集划分，整理自己的UV0。
2. 确定低模拓扑、硬边、平滑和需要保留的自定义法线；准备最终烘焙所用三角化方案。
3. 画D基础色，先确认UV位置正确；烘焙AO/普通法线作源素材。
4. 分开绘制粗糙度、金属、透明、ID，再打包衣服控制图。
5. 做脸SDF和需要的HET，做头发HM/HN。
6. 处理眼睛UV、视差和高光，再增加FX/尾巴等选用功能。
7. 根据最后的低模法线与UV0切线生成描边UV1，绘制COL0.G等模型控制数据。
8. 转灯、转头、转视角验收，然后再导出供其他工程使用的模型。

低模的法线、UV0或三角化方案改变后，已有法线烘焙和依赖切线空间的描边数据都应重新核对；不要把这些基础改动当成只影响模型外观。

<a id="make-3"></a>

### 3. 衣服D：怎样画固有色和闭塞

**心月狐参考：** Cloth/Up/Down各一张2K的D，里面的皮肤、饰品、布料可以共用图集。原D.Alpha中性区域常见102。

#### RGB工作方法

1. 从材质分区开始铺大色块：红布、浅布、皮肤、金属分别独立图层。
2. 画印花、刺绣、包边、接缝等设计信息。结构清晰的花纹优先保证形状与UV位置。
3. 用烘焙AO、曲率等辅助定位褶皱和接缝，但按二次元风格清理噪声、控制对比。
4. 保留想固定的手绘细节和色彩变化。大面积主光方向、投影边界与动态镜面高光留给工程计算，避免旋转灯光时两套光照打架。
5. 在模型上看正侧背面，确认接缝连续、花纹没有被拉伸；不能只看平面颜色图。

#### Alpha工作方法

先获得白=无遮挡、黑=闭塞的AO工作图。可以从高低模烘焙或模型自身烘焙开始，再手工清理：减少大片脏黑，保留接缝、夹层、小缝隙等必要压暗。

当前闭塞映射使用A=0.02～0.25。将AO工作图映射为 `A=0.02+0.23*AO`，8bit约5～64。不需要闭塞的普通区域可按原图填102，仍然是无遮挡且不发光。

要发光的区域再单独写高于约127的Alpha：约191为半强度控制、255为满控制；最终亮度由发光模块强度等决定。一个Alpha同时承担这些编码，发光区域不能独立保存另一份任意AO，需要先接受这一入口的限制。

**验收：** 关闭额外发光时普通颜色正常，闭塞只在目标部位压暗；打开后只指定装饰亮起。不能把整张D导成Alpha255。

<a id="make-4"></a>

### 4. 衣服N：法线和粗糙度怎样做

#### 先烘焙普通切线法线源图

1. 高模准备褶皱、接缝、浮雕等细节；低模先确定UV、平滑与硬边。
2. 高低模匹配位置。投射范围或cage包住需要捕获的高模细节，避免抓到相邻衣片、身体或背面。
3. 最终低模的三角化与切线基础尽量与烘焙时一致。不要烘焙后随意翻三角、改硬边或重展UV。
4. 烘焙出普通切线法线，先在模型上检查凸缝、凹缝和UV接缝，再清理误投射。

如果用Blender烘焙，建议在专门的烘焙副本/场景中用Cycles完成：低模材质准备目标图片并选中对应图片节点，高模选中、低模为活动对象，使用Selected to Active的Normal烘焙与适合的cage/投射范围。不要直接把带NPR专用节点的原渲染场景切换当成现成的烘焙设置。

#### 适配这套N入口

当前 `绿法线转法线` 使用R/G、反转并重建第三分量，输入B不参与恢复。现有转换设置在XY上保留输入R、反转输入G，因此普通OpenGL源图的G反向需要核对。若以相同XY方向为目标，可先试R保留、G=1-G、B=0，再以凸缝试灯确认；这不是完整三维向量逐项等价的保证，第三分量仍按现有组重建。

新图无凹凸的区域输入RG约(0.5,0.5)，B可以0。不要对RG执行sRGB调色或把它当黄色图去调饱和度。

#### 单独制作粗糙度

用材质类型铺底，再添加适量变化：布料偏粗糙，皮革中等，抛光装饰偏光滑；磨损、接缝、涂层可以局部调整。不要直接将D转灰度当粗糙度，颜色深浅不等于表面粗糙度。

建议初稿8bit值：粗布200～245、皮革100～180、光滑装饰40～100。它们是起步值，不是强制规范。最后放入N.Alpha，RGB法线数据独立保留。

**验收：** 先侧光检查一条已知凸缝的方向；再固定光照检查粗糙度是否控制亮斑宽窄。某个岛整块发黑应先排查模型法线、投射与切线方向，不能一律归因于粗糙度。

<a id="make-5"></a>

### 5. 衣服FTM：三张工作遮罩合成一张

#### R不透明度

实体布料直接白，不必烘焙AO来代替透明。发片/蕾丝/镂空按设计画形状，剪掉部分黑，保留部分白，柔边适度灰。在线稿与UV边界之外留适合的扩边，防止缩小贴图或过滤时出现意外白边/黑边。

薄纱灰度需要在最终材质中看前后层、背景与排序；灰色不是一个保证物理正确的固定厚度值。

#### G金属度

按材质本身画区域：皮肤、普通布料、非金属皮革黑；金属饰物白或需要的灰度。金色布料、黄色塑料不因为颜色像金属就一定填白。先画明确区域，再按磨损/涂层需要细分。

#### B战损

当前三套衣服主要可见链没有使用这一输出。照心月狐原数值可先填126；先不制作复杂战损图。以后启用战损效果时再确认其白黑方向与具体接入功能，不能单凭这个名字画通用刮痕就宣称生效。

打包R/G/B，不使用FTM.Alpha控制这里的透明。普通实体布料初稿可为(255,0,126)，纯金属(255,255,126)。数据图片使用Non-Color。

<a id="make-6"></a>

### 6. RGID：从模型材质分区制作编号图

1. 先列区域表：例如区域A红布、B皮革、C装饰、D皮肤；编号的含义由你这份材质接线决定。
2. 可先在模型上分临时材质ID，用无光照的纯色/数值输出烘焙到UV，或直接在UV图上填区域。
3. 将普通彩色ID转换为目标灰度编号。照心月狐可以用0、16、32、48、64，RGB三个通道一致。
4. 保留清楚的内部纯值，边界适度处理与扩边。不能用AO、颜色噪声或大渐变作为编号内部变化。
5. 在材质中将 `ID选区` 位置对应到转换后的值，约0、0.284、0.389、0.468、0.534；同时核对该节点接的是调色、Matcap还是别的效果。

不要直接把Substance等软件的红绿蓝材质ID作为这套灰度编号使用。数据图Non-Color，转换组内部已有Gamma处理；额外再做同一Gamma会改变位置。

**验收：** 暂看选区黑白结果，白只覆盖目标区域。RGID贴图编号与几何节点生成的整数属性 `ID` 是两种数据，不能互相混用。

<a id="make-7"></a>

### 7. 脸D、SDF与Face_HET的制作方法

#### Face_D

用自己的脸UV画肤色、腮红、眉眼妆容、嘴唇、脸部纹样；左右不对称设计要在UV中保留可独立绘制的空间。小范围必要的手绘阴影可以保留，大块动态鼻影交给SDF。Alpha按闭塞约定处理，初稿普通区域可102。

#### 从阴影设计制作SDF

这一工程的SDF是一张“进入阴影的阈值场”。能从已有正确SDF适配就优先适配，不能把普通AO、曲率或某一方向的阴影烘焙直接当最终SDF。

从零做的可执行思路：

1. 用自己的脸UV，在一侧光照0°、30°、60°、90°、120°、150°、180°下设计目标亮面/暗面，重点看鼻子、脸颊、嘴周。可以拿烘焙/渲染阴影作参考，但最终按角色风格修形。
2. 所有角度参考都转换到同一脸UV。不能把屏幕上的脸轮廓图直接当UV图。
3. 对每个UV位置确定它从亮转暗的角度θ；中间角度间按目标变化插值。当前比较阈值是 `0.5-0.5*cos(θ)`，因此把对应值作为该点的SDF。
4. 例如某点希望约60°进入阴影，阈值约0.25；约90°进入则0.5；约120°进入则0.75。8bit分别约64、128、191。当前过渡宽度会使转换发生在一个角度区间，而非完全瞬时切换。
5. 同一侧某点若随角度反复亮暗，一张当前形式的单阈值SDF不能完整表达，先清理设计或接受近似。
6. 平滑阈值场中不需要的噪点，但保持鼻影/脸影形状。不能用模糊来掩盖左右或UV错误。
7. 灰度同时写入RGBA，当前RBA均值才读取到原灰度。Non-Color，CHANNEL_PACKED。若正面或背面端点受软过渡影响，可结合目标效果试验端点限制；不应盲目改掉所有原图数值。
8. 当前按U与1-U镜像采样，镜像中心0.5。设计与UV需能支持这个约定；任意打散UV后不能期待左右鼻影自动正确。

已有其他来源的SDF时，先核对其各通道含义与左右编码，再针对这份模板适配；不要假定任何红绿图都能用同一公式完整恢复。

#### Face_HET

按自己脸UV画目标眼透区域：需要允许眼透叠加的区域白，其他黑；如果眉睫也要透，按目标一起画。制作时将遮住眼睛的刘海摆在实际位置，预览 `eye_mask` 后修边，避免耳朵、脖子也被透出来。

当前这一路有大于0.5的门限，纯黑白图最容易判断。它不等同于可以随意画一个灰色柔边就获得同样柔边眼透。原图的白块坐标只属于原角色UV，不能照着图片白块硬贴新头。

两份HET采样都应对应自己的图。关闭眼透及相关局部调色时可省略；不要把Face_HET与眼睛局部调色的Eye_HET合成一个含义不清的通用文件。

### 8. 头发D、HM、HN与HR怎样制作

#### 先整理适合绘制的头发UV

将主要发束按根梢、左右宽度展开成容易连续绘制的岛，尽量减少扭曲；岛不必须全是矩形，但根梢方向最好有清楚标记。不同岛可以旋转打包，前提是你的颜色/控制场沿每个岛正确绘制，而不是让shader从普通UV自动猜出哪边是发根。

发束左右两侧需要不对称高光时，不能无条件重叠镜像岛。前后发共用图集可以节省文件，但要能分别设置材质参数。

#### Hair/Bangs_D

先铺发色，再按发束分组画根梢变化、挑染和克制的手绘纹理。固定的大亮条会与动态高光叠加，要留意两者强度。Alpha按闭塞约定；发片透明放FTM.R。

#### HM.R：高光允许区

先画黑底。按发束走势选允许出高光的区域，可画清楚、较克制的条状或片状白区，再调整边缘灰度。心月狐原HM.R大部分黑、部分白条。

不要整头先刷白再靠压强度补救。也不要把每个最终高光像素都画死：这张图控制允许区，最终位置还由HN与动态参数决定。

#### HM.G：局部二分偏移

初稿可以先0，通过全局阴影偏移获得整体结果；再按发束修局部偏移。当前贡献约为G*0.1，原图常见底值约65～82但有区域变化。它不是一张“黑是阴影、白是亮面”的最终二分遮罩，不能直接把烘焙阴影塞进去期待固定边界。

#### HM.B：局部高光曲线形状

初稿0可以参考原后发；原刘海有局部变化。先挑一束发做0、中灰、白的对照，观察与宽度/凸起强度共同作用的方向，然后再画全头。它不是常规粗糙度，当前宽度运算也不是简单白=宽。

#### HN.G：高光输入场

从每束发的连续灰度场开始，可以先用根到梢0～1的梯度，或根据想让亮带绕过的位置弯曲梯度。把灰度写入G，其他当前未用通道可常量。

一个好用的工作办法是先画几条“同值线”：比如希望当前亮带经过的各发束位置都约G=0.5，然后分别向两侧渐变。这样跨发束的位置容易对齐。0.5本身不是永远亮的位置，实际亮带还要用偏移/宽度调到它。

先单色高光，看范围、位置和运动，再回渐变模式。发束高光断了先查HN.G连续性与HM.R；高光整体位置错先改偏移或输入场。原HN为256²，原HM为2K，说明位置场和精细允许区可以用不同尺寸但同一UV。

#### Hair/Bangs_FTM

R画发片的保留形状与柔边：白实体、黑去掉、灰过渡。刘海眼透/折射要在实际NPR链检查；它没有因FTM画好就自动完成。实体后发没有空间变化需求时可用常量代替这一文件。

#### HR色带

可以先复用原512×4色带。要自己做，沿横向画所需的高光颜色变化，少用过多互相冲突的色段；若只用一行风格，四行可保持一致。原模块还允许选择RampY轴，需要多行效果时再明确每行对应哪套配色。

调范围先单色，调配色再HR；避免因颜色太深误判HM/HN没起作用。

<a id="make-9"></a>

### 9. 眼睛D与Eye_HET

把自己的虹膜、瞳孔中心与眼睛UV关系确定清楚。先做颜色D并在模型上看中心、大小与形变，再启用视差和动态高光。眼睛不是随便展UV后仅换一张图就必然与模板一致。

D里画虹膜分层、瞳孔、眼白和需要固定的细节；动态点高光有专门资源，避免又在D中画很强的大点导致双高光。原图的手绘高光可以作为风格参考，是否保留由目标画面决定。

Eye_HET只是局部HSV系数：希望受调色的虹膜白，不希望受调色的眼白黑，过渡处灰。原图256²、sRGB，应在当前调色链看过渡，不能拿Face_HET替代。

`T_HDMF_EM`视差/高光图集先复用；需新高光形状时再按实际图集结构制作，不把普通颜色图放到这个入口。

<a id="make-10"></a>

### 10. Up_FX与尾巴附加图

#### Up_FX

RGB制作流动亮纹/噪声素材，Alpha按衣服UV画允许显示范围。当前RGB经运动UV采样，Alpha用原UV遮罩：设计时可让流动图案较通用，但Alpha必须落在自己的衣服区域。先固定时间看遮罩，再播放看移动是否越界。它与D.Alpha的发光编码是两个入口。

#### Tail_D与Tail_ID

Tail_D画根尖毛色、条纹及适量手绘细节；内部还有图像闭包读D，换图时两处都换。Tail_ID当前主要取R参与局部不透明度，按尾巴实际UV画毛片保留轮廓，黑空白留、必要处灰。

#### Tail_RGID与角色_M

Tail_RGID按尾巴分支需要编号，原常见1/4等低灰度，解码位置与衣服不同。角色_M实际读Alpha，采样UV2：先决定毛片/区域在UV2中的遮罩布局，再画羽状/毛束轮廓渐变等目标范围。不能只把Tail_D的UV岛复制过来而不核对M。

#### FurHeight与Flow

通用FurHeight是毛纹高度/可见性素材，可以先复用；自制时用适合疏密的点/毛纹和灰度高度变化，再与layer一起检查，不能把它当单层模型直接长毛的图片。

当前Flow映射RGB到-1～1后扰动毛纹UV，幅度随层值变化，可以先复用。制作自己的图时，先看它在当前入口读取后的数值，再设计方向扰动。原Flow图片设为sRGB，因此原入口里字节128不等于线性0.5；若要线性中性0.5，sRGB字节约188。不能既沿用原色彩空间，又把普通数据图的128中性值直接套进去。

普通尾巴入门先处理D/必要透明；体积毛另需几何和属性，不能仅凭图数判断已完整设置。

### 11. 模型法线：四种相关数据怎样区分

| 数据 | 储存位置 | 负责什么 |
|---|---|---|
| 几何面法线 | 模型拓扑/面朝向 | 判断正反面、基础几何方向 |
| 平滑/分裂/自定义着色法线 | 模型每个面角 | 大形体的受光、阴影、边缘光、法线贴图的基础 |
| 切线法线贴图 | N的RG，经转换 | 褶皱、缝线等局部表面细节 |
| 描边外扩法线 | 本工程UV1编码，经解码 | 描边壳外扩方向，避免不想要的裂缝/尖角 |

HN是头发高光输入场，不属于上表的普通N法线贴图。

#### 几何与着色法线的制作

先检查面朝向，修正明显反面、重复面和无意重合。需要双面的薄片不因此把整个模型随机翻面；应按薄片材质/实际拓扑设计处理。

衣服大曲面先平滑，金属或结构折角按设计保留硬边。细小褶皱可放N，轮廓与大的结构变化靠模型。Weighted Normal等适合的法线调整可用于某些硬表面，但不应全角色无差别套用。

脸部可从正常平滑开始，鼻尖、嘴角、眼窝的错误二分若来自着色法线再局部调整。需要特殊二次元法线时，可用形状合适的光滑参考体传递大方向，再修正不合理区域；不是统一把全部脸法线设成向前。SDF负责主脸影形状，但法线仍可能影响边缘光等其他链。

头发可在每束发内获得连续的大方向，减少不需要的多边形碎亮；相邻但空间分离的发层不能不分组地全部平均。需要在发束间连贯时，可用合适参考形状转移并保留边界。

心月狐八个原部位当前都带自定义法线，导入后要保留/核对，不要先“重算法线清空全部”再期待原效果。`custom_normal`是当前网格上的内部自定义法线存储，不是要求你画一张同名图片，也不能直接当UV1数据复制。

#### 切线和副切线

切线建立纹理UV方向与模型表面的关系。当前GGX高光的默认切线明确来自UV0，普通Normal Map使用其对应的纹理切线基础。因此UV0的旋转、镜像、接缝和退化岛都可能影响方向性高光/法线。

切线通常由模型法线、UV和拓扑计算，不是另外画一张图。烘焙和导出使用一致的基础；镜像UV需要正确手性，不把不同面角的切线强行合成一个顶点方向。UV面积几乎为零的面不适合作为可靠切线基础。

### 12. UV0/UV1/UV2/UV3各自怎样准备

| 层 | 心月狐当前用途 | 制作方式 |
|---|---|---|
| UV0 | 原八部位活动渲染UV；主贴图采样、GGX默认切线 | 正常展开、整理岛、画图与烘焙 |
| UV1 | 描边组明确将它按八面体法线解码 | 从描边方向计算并编码，不是普通Unwrap/Pack |
| UV2 | 尾巴M.Alpha采样和沿V的效果渐变 | 按遮罩图集/根梢渐变要求安排第二套纹理坐标 |
| UV3 | 原模型有数据，但这次检查的有效节点没有发现明确显式读取 | 保留原资产时不随意删；新角色当前无需为未知用途强做 |

命名和层序号是两件事。节点写`UV1`时按层名找；以后导出到别的软件/Unity还要核对UV槽序号。这里的UV1没有被定义为烘焙灯光UV，不能照其他工程的命名习惯套用。

#### UV0制作原则

按图集分部位；主要可见区域给足面积、控制拉伸，检查棋盘格。脸保持可预测的左右关系以匹配SDF镜像；眼睛保持与模板采样对应的中心/比例；头发便于沿束绘制连续控制场。

镜像/重叠能节省面积，但会共享图案、遮罩和法线数据；要不对称脸妆、头发高光或独立材质控制时留独立区域。岛间留满足最终尺寸/缩小过滤的间距与扩边，不能只看大图中没有重叠。

复制给其他槽之前先弄清用途。检查显示Cloth/Up/Tail等的UV2并非整体等于UV0；不能因为几个采样点一样就判断整层可替换。

#### UV1描边编码的完整思路

当前真实路径：`UV1 → 八面体解码 → n*0.5+0.5 → Tangent Normal Map → 外扩`。所以给新模型制作时，目标方向需要适配这条切线空间路径；把对象空间平滑法线直接编码进去通常会被再次当切线法线变换。

1. 先确定想要的描边外扩方向。可以从同一结构内连续的平滑法线开始；硬边附近可共享更平顺的外扩方向，但彼此贴近的衣层/发层不能全部焊在一起平均。
2. 保留渲染低模实际的分裂/自定义法线；确定UV0和三角化基础。
3. 对每个面角取得UV0对应的切线T、副切线B和着色法线N，将目标对象空间描边方向转成切线坐标 `(dot(D,T), dot(D,B), dot(D,N))` 并归一化。切线手性要匹配渲染器。
4. 将三分量方向做八面体压缩得到二维p；当前解码起点是 `f=UV1-(0,1)`，所以相应保存U=p.x、V=p.y+1。它不是常规将p整体映射到0～1的另一种打包约定。
5. 写入名为UV1的每面角数据。镜像岛、硬边和不同切线基础的角可以有不同编码，不能只按顶点编号写一个值。
6. 解码后与目标方向比较，再在实际描边中看裂缝、尖角、凹陷与距离变化。根据效果修平滑分组和COL0.G，不能只验证“存在UV1”。

Cloth当前实测UV1约U=-0.9985～0.9961、V=0.0107～1.9829，与上面的代码一致。GLSL注释写过0～1，但实际代码和资产值不按那个注释范围；不要做归一化Pack。原Eye的UV1数据分布不同，不能只凭同名就断言所有部位都已经使用同一种美术编码，应按该部位是否需要描边独立核对。

这通常通过预处理脚本/工具生成，不是模型师手动拖几万个UV点。这里说明的是适配思路；使用生成工具后仍须核对解码与实际外扩效果。

#### UV2制作原则

对尾巴M的遮罩，将需要共用的轮廓组织到对应岛位；沿V还用于渐变，因此让相应区域的V方向与想要的根梢/效果变化一致。先显示M.Alpha，再显示纯V渐变，分别验证图案位置和渐变方向。

普通衣服/脸/头发的主图片没有因此全改读UV2，新角色不必每个部位都强制展开另一套遮罩UV。

### 13. COL0、透明修正、ID、毛层属性怎样做

#### COL0顶点色

原八部位都有CORNER域BYTE_COLOR的COL0。它是网格数据，不需要另外一张PNG。

描边取G并经过约0.4645次幂后乘宽度：G越低越细，0为零宽度贡献；1为满贡献。先给需要的区域合理统一底值，在发尖、小饰品、内侧等位置按设计降低；高密度区域可柔和过渡，低模顶点少时很细的控制可能需要增加合适拓扑或接受插值。

脸根材质的顶点色B还控制不同边缘光链：其中一支读B，另一支读1-B。因此B不能随手整头填白然后认为所有效果都保持中性；要按想保留的边缘光预览后调整。当前脸节点层名为空，还要确认实际活动颜色层，创建一个COL0不代表它立刻成为被读取的层。

R/A在不同资产或功能里可能保留其他信息，这次检查未确认全角色统一用途；不要为了画G而把其他通道全部覆盖。BYTE_COLOR还有颜色空间转换，8bit128不一定等于shader线性0.5，调宽度时以实际效果/读取值为准。

#### 描边排除

当前读“描边排除”后在轮廓颜色与透明之间混合：0保留这一路描边、1走透明。可以在需要完全排除的区域提供同名0～1属性，而局部变细优先用COL0.G。

#### 整数ID，和RGID图区别开

描边几何节点按来源写实例整数ID：头发/刘海0、Cloth1、Up2、Down3、脸/眼睛4，供外层描边材质选不同颜色和宽度。这是工程生成的模型/实例属性，不是再画一张整数ID贴图。

几何组还显式引用原对象。把自己的头赋上材质，并不会自动让那组Object Info读取自己的头；新角色需更新来源或建立自己的描边对象/引用。这也是描边适配的一部分，不是贴图问题。

#### 透明修正

刘海NPR读取名为“透明修正”的顶点色，与FTM.R经曲线后的值做最大值。做此层时灰度RGB一致：黑让FTM继续决定，白将这条混合拉向头发不透明端；按实际区域调。

当前原刘海基础网格只查到COL0，没有“透明修正”颜色层，不能把节点引用存在当成原资产一定提供了有效控制。需要这个功能时在自己的模型明确准备对应层并预览，不能盲目假定缺失层的回退值。

#### layer、sm_nor与毛

启用毛层时，layer表示各层相对位置；sm_nor给毛层使用的连续法线；“毛”控制普通表面/毛层分支。它们应随毛层几何一起生成/传递，不能只给单层模型手工全填一个layer就等于32层毛。

现有“多层毛发”组会写layer和sm_nor，但这次检查的这个组未写“毛”，且尾巴修改器关闭。搭建自己的完整分支时，需要按实际材质读法补相应标记：普通表面与毛层可用0/1区分，并验证分支。层数、总厚度和法线方向共同决定毛体积，贴图负责毛纹/可见性。

### 14. 给自己新角色的一次练习任务

先选一块有凸缝、一个金属饰物和一处镂空的衣服：D画三者颜色，Alpha普通102；N用凸缝法线、A分别粗糙/光滑；FTM用R控制镂空、G分金属；RGID为三块分配不同编号，预览选区。这样四张图的用途都能独立验证。

再选三束相邻头发：HM.R画允许区，HM.G/B先常量，HN.G画连续输入场，调出跨三束的连贯高光后转视角。不要第一步直接画完整头发后才找错误。

脸接入符合当前解码的SDF，检查±60°鼻影，再试侧后方与转头；需要眼透时另做Face_HET。描边最后准备COL0.G和UV1，先验证一小块模型的编码/外扩方向再扩到全角色。

验收分三轮：第一轮颜色与UV，第二轮独立控制图与法线，第三轮动态灯光、视角、描边和透明。所有入口有效后，再增加流动FX与毛层。
